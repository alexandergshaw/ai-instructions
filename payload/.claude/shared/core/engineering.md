# Engineering Standards

- Inspect the existing code before introducing new abstractions.
- Preserve existing public APIs unless the task explicitly requires an interface change.
- Prefer the smallest correct change that fully solves the stated problem.
- Do not disable functionality merely to make tests pass.
- Do not remove tests to hide failures.
- Run the relevant validation, tests, or build checks after making changes.
- Preserve compatibility unless requirements explicitly change expected behavior.
- State assumptions when repository behavior or requirements are ambiguous.
- Avoid unrelated refactoring while implementing the requested change.
